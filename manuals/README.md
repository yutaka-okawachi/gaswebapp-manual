# 運用マニュアルの入口

初めて担当する人も、同じ担当者がPCを替える場合も、このページから進めます。公開サイトの使い方は[リポジトリREADME](../README.md)、更新作業は以下の順です。各文書の既存URLは維持しています。

## 最初に、自分の入口を選ぶ

| 状況 | 最初に読む文書 | 次へ進める目印 |
| --- | --- | --- |
| 後継者として新しく担当する | [継承者マニュアル](SUCCESSOR_GUIDE.md)第1〜3章 | 自分のアカウントで必要な資産を開け、既存の実行主体・秘密情報の保管先を確認できる |
| 本人が新しいWindows PCへ移る | [PC移行マニュアル](PC_MIGRATION_GUIDE.md)第1章から | 未送信作業を保全し、新PCで認証・設定・初回ローカル確認を終えている |
| 設定済みPCで日常更新する | 本ページの「3. シート編集と検証」から | 対象データと公開範囲を決めている |

新PCの準備後は、後継者も本人も「3 → 4 → 5 → 6」の共通手順に合流します。譜例追加が不要な更新では5を飛ばし、6を復旧時の参照先として控えます。

<a id="overview"></a>
## 1. 概要と、どこを直すか

データの流れは **Googleスプレッドシート → GASの認証付きスナップショット → PCの同期処理 → GitHub → GitHub Pages** です。シートの保存だけでは公開サイトは変わりません。GAS自体はGitHubへ書き込みません。

| 正本・構成要素 | 内容と関係 |
| --- | --- |
| `GM` / `RW` / `RS` タブ | Mahler / Wagner / Richard Straussの指示原文、訳文、使用箇所。作品・楽器等の検索と「用語から検索」の元データ |
| `Notes` タブ | 用語集の見出し・本文・出典。検索結果の用語リンク、用語集、「実例を見る」につながる |
| 日英の列 | `de`＝ドイツ語原文、`ja`＝日本語本文、`en`＝英語本文、`ja_old`＝保存用の旧日本語。RW/RSの`whom`・`whom_en`は指示対象。英語本文が空欄でも日本語で自動補完しない |
| 補助タブ | `語形対応`、幕構成、楽譜情報、略記一覧、`synopsis`等。列契約は[日常保守第2章](DEVELOPER_GUIDE.md#2-2-実行される処理の流れ)と[日英統合同期](BILINGUAL_SYNC.md) |
| `src/` | GAS、辞書生成器、共通表記処理等のソース。固定GAS APIは本リポジトリが担当 |
| `frontend/`・`scripts/` | 検索画面のソース、組み立て・同期・検証。編集元一覧は日常保守第2章 |
| 公開生成物 | `mahler-search-app/data/`、`dic.html`、`js/app.js`、英語版`en/`等。シートや生成元を直して再生成し、生成物を直接修正しない。`src/sync_build.js`も生成物 |
| 管理者ダッシュボード | GASの集計APIを使う別の画面用リポジトリ・Sitesプロジェクト。[ダッシュボードマニュアル](DASHBOARD_GUIDE.md)を参照。本リポジトリのcloneだけでは画面の開発環境はそろわない |

**成功の目印：** 修正する内容の正本を説明できる。**次：** 2へ。判断できない場合は[編集元一覧](DEVELOPER_GUIDE.md#編集元と実装の分担)を確認し、生成物への直接修正を始めません。

<a id="setup"></a>
## 2. 権限と新PC設定

**前提：** 対象のGitHub・Googleアカウント、既存シート・GAS・公開先が特定できること。

1. 後継者は[継承者第3章](SUCCESSOR_GUIDE.md#3-前任者から引き継ぐ情報権限チェックリスト)でアクセスを取得します。本人のPC交換では既存権限を確認し、クラウド資産を作り直しません。
2. [PC移行第2〜4章](PC_MIGRATION_GUIDE.md#2-ツールと作業フォルダ)でツール、repo配置、GitHub/Google再認証、`.env`と`.clasp.json`、初回確認を順に進めます。
3. 閲覧用ブラウザに[管理者オプトアウト](ADMIN_BROWSER_OPTOUT.md)を設定します。これは計測除外であり、権限付与や認証ではありません。

**成功の目印：** ローカル準備が完了し、公開を伴う操作との違いを理解できる。**次：** 3へ。認証・権限に失敗した場合はPC移行第6章へ。ローカルCheck成功だけでは本番アクセスを確認したことになりません。

<a id="edit"></a>
## 3. シート編集と検証

**前提：** 2が完了し、編集担当と範囲を決めていること。

1. 原譜・根拠と対象の作品・使用箇所を照合し、該当する`de`・`ja`・`en`等を編集します。物理行番号だけで対象を決めず、見出し・本文・使用箇所を照合します。
2. 数式・正規化列・見出し・旧日本語・関係のない行を保全し、保存後に読み直します。日常保守第2章の列契約を確認してください。列移動や大量削除は通常の本文修正と分けます。
3. 辞書候補の採否・登録は[日常保守の辞書候補ワークフロー](DEVELOPER_GUIDE.md#辞書候補ワークフロー)に従います。旧英訳確認メニューの再導入・再実行は不要です。
4. 譜例を追加する場合は先に5へ進み、コード対応→シートの順を守ります。

**成功の目印：** 元シートの保存値が意図した文面で、数式・使用箇所・日英の対応が保たれる。**次：** 4へ。元データが違う場合は公開前に直します。ローカルプレビューは前回取得データの表示であり、今保存したシートの読戻し確認にはなりません。

### Notes本文の参考資料リンク

Notesの日本語本文（見出し名 `ja`、現在B列）・英語本文（`en`、現在C列）では、本文末尾へ次のようなプレーンテキストを追加できます。日本語は「参考資料」、英語は「References」を見出しにし、各資料を別の行へ書きます。

```text
参考資料
[IDS grammis：achten auf（注意を向ける）の語義・構文](https://grammis.ids-mannheim.de/verbs/view/400210/1)
```

保存記法は `[資料名](https://...)` です。英語列では資料名を英語で書き、同じ参照先URLを使います。複数資料も同じ記法で追加できます。長期運営される辞書・研究機関等の個別語義・恒久リンクを優先し、本文と語義が一致するか確認してください。シートのリンク装飾やHYPERLINK関数、生HTMLに置き換えず、この文字列自体をセルへ保存します。

サイトはhttp/httpsだけをリンク化し、資料名とURLを内部用語リンクへ重ねて変換しません。資格情報・制御文字を含むURL、不正な記法、未対応の記法（画像・リンクタイトル等）は安全な文字表示になります。クエリ・PDFの `#page=31`・URL内の対応する丸括弧は維持します。既存本文・改行・譜例トークンを残して追記し、保存後に読み直してください。シート保存だけでは公開されず、公開する際は承認範囲を確認して通常のデータ同期を行います。


<a id="publish"></a>
## 4. 同期と公開確認

**前提：** 公開してよい変更だけが作業フォルダにあり、main・origin・他担当の作業・未完了Git操作を確認できていること。同期は許可対象の未コミット文書等もまとめてコミットするため、別作業を混在させません。

シートの変更を反映するときは **`.\sync-data.ps1 -Mode Data`** を使います。`02_RUN_SYNC.bat`はAutoです。Autoはシートの変更履歴を見て判定せず、ローカル変更とGASの差により取得を省略する場合があります。モードの正本、実行前確認、完了の判定は[日常保守第1〜2章](DEVELOPER_GUIDE.md#1-日常の作業)に集約しています。

**成功の目印：** 「同期完了」、対象コミットのPages成功、公開ファイル一致、必要なAPI検査の成功。その後、管理者モードの日英画面で修正箇所・通常検索・辞書実例を確認します。**次：** 継続運用へ。失敗時は6へ。GitHub push成功だけで公開完了とは扱いません。

<a id="scores"></a>
## 5. 譜例を追加する

**前提：** 原譜と採用図、追加先の文脈を確定できること。

[譜例トークンの仕様と追加手順](SCORE_EXAMPLE_TOKENS.md)で、まず対応範囲表を確認します。新規追加は **SVG描画＋registry登録＋シートの`[[score:<id>]]`** が必要です。5件のID表は全譜例一覧ではありません。コードと旧データ互換を検証・公開してから、シートのde/ja/enを変更し、4のData同期へ戻ります。

**成功の目印：** 対象欄だけに一枚ずつ表示され、検索・辞書アンカー・狭い画面で支障がない。**次：** 4へ。未登録IDや誤文脈の説明が出る場合は、トークンを増やさずregistry・描画・対象データを照合します。

<a id="recovery"></a>
## 6. 障害復旧

**前提：** 止まったコマンド、モード、最後の成功段階、現在のGit状態を控えていること。秘密値をログや報告へ貼りません。

| 症状 | 調べる場所・次の操作 |
| --- | --- |
| ツール・GitHub・Google認証・設定不足 | [PC移行第6章](PC_MIGRATION_GUIDE.md#6-途中で止まった場合) |
| GAS編集版の未統合差分、列不足、件数減少、生成物変更 | [日常保守第2章のトラブルシューティング](DEVELOPER_GUIDE.md#2-5-トラブルシューティング)。停止理由を解決してから再実行 |
| push後のPages/API確認が未完了 | 同じ日常保守第2章。既存の公開記録を確認し、同じコマンドまたはVerifyで再開。Verifyはpushを含み得る |
| 元データ・コードを戻す必要がある | [日常保守の復元手順](DEVELOPER_GUIDE.md#2-4-復元手順)。生成物直編集や未確認の強制pushで復旧しない |
| ダッシュボードだけ開けない・集計できない | [ダッシュボードマニュアル](DASHBOARD_GUIDE.md)。画面側とGAS APIを切り分ける |

**成功の目印：** エラーの原因と影響が分かり、必要な再開・修正後に4の公開確認を終えている。**次：** 通常運用へ。不明なら停止段階と未確認事項を次の担当者へ残します。

日付付きの「未反映」「今回」「次の同期」は、その作業時点の記録です。現在の公開状態は同期結果・対象コミット・公開ファイルで確認します。秘密値や実デプロイIDはこの文書群へ追記せず、安全な保管先へのアクセスを引き継ぎます。

英語 Notes 本文で日本語訳を対訳例として引用する場合，英語グロスを併記し，承認済みの完全一致引用を `scripts/english-approved-citations.json` に登録します．一般の未翻訳本文や画像属性はこの例外の対象にせず，`test-english-citations.js` と実際の同期公開ゲートで検証します．
