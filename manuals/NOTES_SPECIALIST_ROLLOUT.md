# 辞書編纂AI：Notesの日英補足

Notesの「選択行を編集」で基準言語を選び，「辞書編纂AIに相談（日英の補足）」を押す．基準側の修正版に合わせた日英の補足案を並べて確認し，「日英の草案を採用」してから「変更を保存」で2言語を一緒に保存する．どちらかの補足がない，複数段落，リンク入りの場合はこの機能の対象外．従来の「AIに相談」は従来どおり選んだ言語だけを編集する．

辞書編纂AIに送るのは保存済みの選択行の見出し・基準言語・その言語のリンクなしの補足1段落・指示のみ．もう片方の既存本文・用例・出典・楽譜リンク・会話履歴は添付しない．草案は自動保存せず，他の段落やセルは変更しない．AIが返した2案は，留保や意味にずれがないか人が確認する．

## 初期設定（管理者のみ）

1. 専用のOpenAI APIプロジェクトに辞書編纂AIを作り，検証済みの設定を複製する．ツール・外部接続は無し．Default projectおよび1日限定のテストキーは本番に流用しない．
2. 専用プロジェクトで本番用の Restricted キーを発行し，Agents と Model capabilities 内の Responses だけを Write にする．All は使わない．発行時にその場で権限を絞れないサービスアカウントの代わりに，初回は管理者所有の専用キーを使う．最初の有効期限は30日とし，期限前に新しい専用キーに差し替える．
3. Apps Scriptの編集権限が管理者だけであることを確認する．プロジェクトID・エージェントIDは先にコードで指定する．専用キーは本番Apps Scriptの固定プロパティ OPENAI_NOTES_AGENT_KEY に管理者自身が1度だけ入れる．既存の OPENAI_API_KEY は変えない．キーをチャットやコードに書かない．
4. 本番反映前に架空データで API 接続とセッション削除を確認する．反映後は本番 Notes で新旧ボタンの表示を確認する．本番データで試す場合は，その送信の承認後に公開済み補足1段落で草案の表示だけを確認する．本番セルは上書きしない．

## 停止とデータの取り扱い

問題があれば OPENAI_NOTES_AGENT_KEY を削除して専用ボタンだけを無効化する．キー自体を無効にする場合はOpenAI側でも失効させる．キーまたは送信先のIDが未設定ならボタンは出ない．

Agents APIはセッション状態を保持する．処理後に削除を確認するが，即時完全消去やゼロデータ保持を前提にしない．機密メモや個人情報を指示・補足に入れない．
