# 継承者マニュアル

後継者として新しく担当する人の入口です。資産・権限・アカウント継承を本書で確認し、PC設定と日常更新はそれぞれの正本へ進みます。本人のPC買い替えは[PC移行マニュアル](PC_MIGRATION_GUIDE.md)から始められます。全体の順番は[マニュアルの入口](README.md)を参照してください。

---

## 1. はじめに（プロジェクト資産一覧）

本システムは **Google スプレッドシート** をデータベースとし、**GitHub Pages** で公開されています。後継者が管理すべき主要な資産は以下の通りです。

| 資産 | 役割 | 管理場所 |
|---|---|---|
| **Google スプレッドシート** | マスターデータ（用語、訳例、メタデータ） | Google ドライブ |
| **Google Apps Script (GAS)** | 同期用スナップショット・辞書生成、検索通知・集計API | スプレッドシートの「拡張機能 > Apps Script」 |
| **メインGitHubリポジトリ** | ソースコード、公開サイト、サイトマップの管理 | [yutaka-okawachi/gaswebapp-manual](https://github.com/yutaka-okawachi/gaswebapp-manual) |
| **ルート用GitHubリポジトリ** | ホスト直下の `robots.txt` の管理 | [yutaka-okawachi/yutaka-okawachi.github.io](https://github.com/yutaka-okawachi/yutaka-okawachi.github.io) |
| **管理者ダッシュボード** | 利用状況の集計表示 | Sitesプロジェクトと別の画面用リポジトリ。公開URL・権限は安全な引き継ぎ記録で管理 |
| **公開 Web サイト** | アプリケーションの動作ページ | `https://yutaka-okawachi.github.io/gaswebapp-manual/` |

## 2. 引き継ぎの進め方

**前提：** 前任者または管理者が、対象資産と権限を確認できること。本人のアカウントでアクセスし、他人のパスワードを共有する方法を前提にしません。

| 順番 | 操作 | 成功の目印・次へ進む条件 |
| --- | --- | --- |
| 1 | 第1章の資産を管理者と特定し、第3章の権限・保管先を確認 | 自分のアカウントでシート・GAS・GitHubを開け、固定デプロイの管理者と実行主体が分かる |
| 2 | [PC移行第2章](PC_MIGRATION_GUIDE.md#2-ツールと作業フォルダ)から新PCを設定 | ツール、再認証、設定ファイル復元、ローカル確認が完了 |
| 3 | ダッシュボードも担当する場合は[ダッシュボード第2章](DASHBOARD_GUIDE.md)を実施 | 所有者として開ける。画面開発も担当する場合は別repoの環境を確認 |
| 4 | [入口の第3〜4段階](README.md#edit)で対象データを確認し、合意した初回更新を実施 | Data同期でシート取得と公開確認を終え、日英検索・辞書の修正箇所を確認 |
| 5 | 公開サイト、通知先、ダッシュボードと引き継ぎ記録を照合 | 新担当で運用できることを確認後、管理者と前任者の権限整理を調整 |

権限不足なら第3章で管理者に依頼し、PC設定で止まったら[PC移行第6章](PC_MIGRATION_GUIDE.md#6-途中で止まった場合)、公開更新で止まったら[日常保守の復旧手順](DEVELOPER_GUIDE.md#2-5-トラブルシューティング)へ進みます。シート共有だけではGASの実行主体や公開管理を移管したことになりません。

## 3. 前任者から引き継ぐ情報・権限チェックリスト

前任者・管理者と次を確認します。権限付与や設定変更は対象アカウント・資産・担当範囲を確認してから行います。PC交換だけの場合は新しい共有・クラウド設定変更は不要です。
*※機密情報（パスワードやトークン、メールアドレス）は、GitHubに直接書き込まず、パスワードマネージャーや口頭、メモ等の安全な手段で渡してください。*

### 3-1. 権限の共有
* [ ] **Google スプレッドシートの共有**: 後継者の Google アカウントに「編集者」権限を付与する。
* [ ] **GAS プロジェクトのアクセス権**: スプレッドシート共有により、後継者が「拡張機能 > Apps Script」からエディタを開けることを確認する。
* [ ] **GitHub リポジトリ**: `gaswebapp-manual`へ自分のアカウントでアクセスでき、公開担当ならWrite以上の権限とPages・Actions等の確認権限があることを管理者と確認する。ルート用`yutaka-okawachi.github.io`はホスト直下のrobots.txtも担当する場合にアクセスを引き継ぐ。通常の本文・データ更新に両repoの変更は不要。

* [ ] **GA4・Search Console**: 後継者が対象プロパティを開け、必要な管理作業を行えることを確認する。
* [ ] **ダッシュボード**: Sitesプロジェクト、画面用リポジトリ、公開URL、所有者アカウントの管理方法を引き継ぐ。詳細は[ダッシュボードマニュアル](DASHBOARD_GUIDE.md)。
* [ ] **GAS実行主体**: 固定デプロイの管理者、実行アカウント、トリガー、GA4読み取り権限を確認する。シート共有だけで運用が引き継がれたとは判断しない。

### 3-2. 安全に引き渡すパラメータ（ローカル用）
* [ ] **GAS Web App URL**:
  後継者の `.env` ファイルに記述する `GAS_DEPLOY_URL` の値。
  *(例: `https://script.google.com/macros/s/XXXXXXXXXXXXXXXXXXXXXX/exec`)*
* [ ] **GAS_SECRET_TOKEN**:
  ローカルPCとGASウェブアプリ間の認証用トークン。GASエディタの「プロジェクトの設定 > スクリプト プロパティ」に設定されている `GAS_SECRET_TOKEN` の値と一致する文字列。

### 3-3. GAS側のスクリプトプロパティ（クラウド側設定）
`DASHBOARD_API_TOKEN` もPCの `.env`、GAS、Sitesの非公開ランタイム設定に同じ専用値を引き継ぎます。32文字以上とし、管理用 `GAS_SECRET_TOKEN` は流用しません。画面のブラウザコードには保存しません。認証移行の順序は[ダッシュボードマニュアル](DASHBOARD_GUIDE.md)を参照してください。

通知先メールアドレスやシークレットトークンは、コード内ではなく GAS の「スクリプト プロパティ」で安全に管理されています。

| プロパティ名 | 設定内容 | 用途 |
|---|---|---|
| `NOTIFY_EMAIL` | 通知先メールアドレス | ユーザーが検索を実行した際の通知送信先 |
| `GAS_SECRET_TOKEN` | 任意の認証トークン文字列 | ローカルPCからの自動同期認証用 |
| `DASHBOARD_API_TOKEN` | 管理用とは別のランダムな32文字以上の秘密値 | Sitesサーバーとローカル検査からの集計API読取り専用 |
| `SPREADSHEET_ID` | データ元スプレッドシートのID | 同期時に読み込むシートの指定。スプレッドシートの「データ同期」メニューから設定可能 |

GitHubの認証はPC側の Git Credential Manager または `GH_TOKEN` で管理します。`sync-data` が公開と状態確認に使用し、GASのスクリプトプロパティには保存しません。

<a id="-gas-スクリプト-プロパティの確認設定手順"></a>
#### GASスクリプトプロパティの確認場所
1. Google スプレッドシートを開き、メニューの **「拡張機能」 ＞ 「Apps Script」** をクリックします。
2. 左サイドバーの **⚙️（歯車アイコン：プロジェクトの設定）** をクリックします。
3. ページ下部の **「スクリプト プロパティ」** セクションへ移動します。
4. **「スクリプト プロパティを編集」**（または「プロパティを追加」）をクリックします。
5. 既存の設定名と安全な保管先を照合します。PC移行だけなら値を変更しません。変更が必要な場合は管理者と影響を確認してから保存します。`SPREADSHEET_ID`の設定には同画面または **「データ同期」＞「このシートをデータ元に設定」** を使います。

## 4. 長期保守・アカウントの継承設定

製作者に万が一のことがあった場合や、連絡が取れなくなった場合に備えて以下の継承設定を推奨します。

### 4-1. Google アカウントの無効化管理ツールの設定
Google の **「アカウント無効化管理ツール」** を使用すると、一定期間アクセスがない場合に後継者へ Google ドライブやスプレッドシートのダウンロード権限を自動で引き渡すことができます。
1. [Google アカウント無効化管理ツール](https://myaccount.google.com/inactive) にアクセス。
2. 待機期間（例：3ヶ月〜6ヶ月）を設定。
3. 通知する連絡先に、後継者のメールアドレスを登録。
4. 共有するデータとして「Google ドライブ」を選択。

### 4-2. GitHub アカウントの継承（Successor）設定
GitHub の `Settings > Account > Successor settings` にて、後継者の GitHub ユーザー名を登録しておくことで、将来的にリポジトリの管理権限を譲渡することが可能になります。

## 5. 技術的な引き継ぎメモ

### 5-1. あらすじ集の構成

RW/RSの日英PDFリンクの列契約・生成は[日英統合同期のSynopsis](BILINGUAL_SYNC.md#synopsis-pdfリンク2026-10-22)、画面・計測の保守は[日常保守](DEVELOPER_GUIDE.md#3-楽譜情報の更新手順)を参照します。

### 5-2. 公開画面とサイドバーメニューの管理（超重要）

利用者向け画面はGitHub Pages、GASはAPIです。編集対象・生成物の扱い・メニュー変更は[日常保守の編集元一覧](DEVELOPER_GUIDE.md#編集元と実装の分担)に集約しています。ダッシュボードのSites画面は別repoです。

<a id="5-3-robotstxt-と2つのgithubリポジトリ"></a>
### 5-3. robots.txtと2つのGitHubリポジトリ

ページ本体とsitemap.xmlは本repo、ホスト直下のrobots.txtだけはルート用repoです。通常更新で公開ページを移動しません。公開URL・Sitemap行の確認とGSC対応の正本は[日常保守第4章](DEVELOPER_GUIDE.md#4-1-seo検索エンジン最適化)です。

## 日常運用への移行

通常の同期はブラウザーでの承認操作なしに公開まで進みます。公開前に画面を確認する場合は `node scripts/preview-site.js --open` を別途実行してください。同期と障害対応の正本は[日常保守マニュアル](DEVELOPER_GUIDE.md)です。シート更新には`-Mode Data`を使います。[マニュアル入口の第3段階](README.md#edit)から、シート編集→同期・公開確認→必要な譜例追加と復旧へ進めます。
